# E6B Trainer — implementation plan

Spec: `docs/superpowers/specs/2026-10-09-e6b-trainer-design.md`. Code lives in `landing-page-svelte/src/labs/e6b/`
(entry `landing-page-svelte/labs/e6b-trainer/index.html`). Mirror the PFD trainer (`src/labs/pfd/`) for structure,
style, comments and idiom: plain JS + JSDoc, Svelte 5 runes, no new dependencies, every `localStorage` access in
try/catch, ES/EN for every user-visible string.

## Shared conventions (contracts — all tasks rely on these)

### Angles and the log scale (`lib/scales.js`)

- Screen angles are **degrees clockwise from 12 o'clock**. SVG point for centre (cx, cy), radius r, angle a:
  `x = cx + r·sin(a)`, `y = cy − r·cos(a)`.
- `theta(v)` = `360 · frac(log10(v))` for v > 0, in [0, 360). The 10 index (any power of 10) is at 0° (top).
- `mantissa(v)` = `10^(1 + frac(log10 v))` in [10, 100).
- `norm360(a)`, `angleDiff(a, b)` (signed, in (−180, 180]).
- Computer-side state `rot` (deg): the inner disc is rotated clockwise by `rot`; inner value v is drawn at screen
  angle `theta(v) + rot`.
  - `rotFor(outer, inner)` = `norm360(theta(outer) − theta(inner))` → rotation that puts `inner` under `outer`.
  - `outerAt(rot, inner)` = mantissa read on the outer scale over inner value `inner`.
  - `innerAt(rot, outer)` = mantissa read on the inner scale under outer value `outer`.
- Markers (outer scale, mantissa positions): `MARKERS = [{id:'naut',v:66,label:'NAUT'},{id:'stat',v:76,label:'STAT'},
  {id:'km',v:12.2,label:'KM'},{id:'gal',v:11.67,label:'U.S. GAL'},{id:'liters',v:44.17,label:'LITERS'},
  {id:'lbs',v:70,label:'FUEL LBS'},{id:'meters',v:15.24,label:'METERS'},{id:'feet',v:50,label:'FEET'}]`.
  Inner indices: `SPEED_INDEX = 60`, `SECONDS_INDEX = 36`.
- Atmosphere (ISA, feet, °C): `deltaP(pa) = (1 − 6.8756e-6·pa)^5.2559`, `tStdC(pa) = 15 − 0.0019812·pa`,
  `sigma(pa, oatC) = deltaP(pa) · 288.15 / (oatC + 273.15)`, `sigmaStd(h) = (1 − 6.8756e-6·h)^4.2559`,
  `densityAltitude(pa, oatC)` = h with `sigmaStd(h) = sigma(pa, oatC)` (closed form),
  `trueAirspeed(cas, pa, oatC) = cas / sqrt(sigma)`, `tasFactor(pa, oatC) = 1/sqrt(sigma)`.
- Windows (base angle constants exported from `lib/scales.js`):
  - `TAS_A0 = 215` (deg). PA mark angle on the disc: `paAngle(pa) = TAS_A0 + 180·log10(deltaP(pa))`
    (disc coordinates, add `rot` for screen). Temperature mark on the base (screen): `oatAngle(c) = TAS_A0 +
    180·log10((c + 273.15)/288.15)`. Aligning PA over OAT ⇔ `rot = tasRot(pa, c) = norm360(oatAngle(c) − paAngle(pa))`
    = `360·log10(tasFactor)` → TAS on the outer scale over CAS on the inner.
  - `DA_INDEX = 330` (screen, fixed on the base). DA mark on the disc: `daAngle(h) = DA_INDEX + 180·log10(sigmaStd(h))`.
    With `rot = tasRot(pa,c)` the DA mark at the index is `densityAltitude(pa,c)`. `daAt(rot)` inverts it.
- Temperature: `cToF(c) = c·9/5 + 32`, `fToC`.
- Time helpers: `fmtHm(min)` → "1:30", `parseHm("1:30")` → 90.

### Wind side (`lib/wind.js`)

- `solveWind({tc, tas, wdir, wspd})` → `{wca, th, gs}`: θ = wdir − tc; `wca = asin(wspd·sin θ / tas)` (deg, + = right);
  `gs = tas·cos(wca) − wspd·cos θ`; `th = norm360(tc + wca)`. Returns `null` if |wspd·sin θ| > tas.
- `findWind({tc, th, tas, gs})` → `{wdir, wspd}` (inverse).
- Wind-face geometry (shared by `WindFace.svelte`, checks and demos), viewBox `0 0 400 470`:
  `WIND = { cx: 200, cy: 190, rDisc: 150, unit: 2.2 /* svg units per kt */, slideMin: 30, slideMax: 270 }`.
  - State: `dir` (deg, rose value under the TRUE INDEX), `slide` (kt under the grommet), `dots: [{b, d}]` (bearing on
    the rose in deg, distance from the grommet in kt).
  - `dotScreen(dot, dir)` → `{x, y}`: a = dot.b − dir; `x = cx + d·unit·sin a`, `y = cy − d·unit·cos a`.
  - Card origin (centre of the arcs/drift lines) on screen: `(cx, cy + slide·unit)`.
  - `readDot(dot, state)` → `{speed, drift}`: speed = distance dot–origin / unit; drift = atan2(dx, −dy) from the
    origin in deg (+ = right of the centre line).
  - `dotFor(wdir, wspd)` = `{b: wdir, d: wspd}` (wind dot, "wind up").
  - Consistency requirement (checked): with `dir = tc`, the dot `dotFor(wdir, wspd)` and `slide = gs` from
    `solveWind`, `readDot` gives speed = tas and drift = wca (±0.01).

### Answers (`lib/answers.js`)

- `parseNumber(str)` accepts `1,5`, `1.5`, `-3`, `+3`; `parseAnswer(str, unit)`: for `unit === 'min'` accepts `h:mm`
  or minutes; returns `NaN` if invalid.
- `isClose(x, field)` with `field = {value, tol: {abs?, rel?}, unit, angle?}`: ok if
  `|x − value| ≤ max(abs ?? 0, rel·|value| ?? 0)`; with `angle: true` compare with `angleDiff`.

### Practice generator (`lib/practice.js`)

- `rng(seed)` mulberry32. `KINDS = ['tsd','fuel','conv','tas','da','wind','navlog']`.
- `generate(kind, seed)` → `{ kind, seed, prompt: {es, en}, fields: [{key, label:{es,en}, value, tol, unit, angle?}],
  setup: StatePatch, demo: DemoStep[] }`. Values are round, exam-style (TAS 90–160 kt step 5, wind dir step 10,
  wind 5–35 kt, distances 20–180 NM, fuel flow 6–14 GPH step 0.5, PA 0–12000 step 500, OAT −15…+35).
  - `navlog`: given TC, TAS, wind, distance, fuel flow → fields `th` (±2°, angle), `gs` (±3 kt), `ete` (min,
    rel 0.03, abs 1), `fuel` (gal, rel 0.03, abs 0.3).

### Store (`lib/e6b.svelte.js`) — the only reactive module

```js
export const e6b = $state({
  face: 'calc',      // 'calc' | 'wind'
  rot: 0,            // computer disc rotation (deg)
  cursor: 0,         // computer-side hairline angle (screen deg)
  dir: 0,            // wind side: rose value under TRUE INDEX
  slide: 100,        // wind side: kt under the grommet
  dots: [],          // [{b, d}]
  pencil: false,     // wind side: tapping the disc marks a dot
  dragging: false    // true while a pointer drag is in progress
});
export function applyState(patch)     // sets known keys, clamps slide, normalizes angles; dots: 'clear' or array
export function resetState()          // back to the defaults above
export function animateTo(patch, ms)  // tween numeric keys (angles by shortest way); Promise; instant with reduced motion
export function addDot(dot)           // max 3 (drops the oldest)
export function clearDots()
```

`StatePatch` = partial of `{face, rot, cursor, dir, slide, dots}`. `DemoStep` = `StatePatch & { say: {es, en} }`.

### Exercises (`content/exercises.js`)

```
{ id, level: 0..4, setup?: StatePatch, part?, explain?, task, hint, why,
  check?: (s, ctx) => boolean,                 // live, evaluated when s.dragging is false
  quiz?: { choices: L10n[], answer },
  answers?: [{ key, label: L10n, value, tol, unit, angle? }],   // typed answers
  demo?: DemoStep[] }
```
Exactly one of `check` / `quiz` / `answers`. `ctx = { lastPart }`. `LEVELS` (5, `{id, name, intro}`), `tasksOf`,
`loadProgress`/`saveProgress` (`qubits.e6b.progress.v1`), `newCtx`. Values in `answers` are computed with `lib/`
functions, never hand-typed. Tolerances for disc checks: `rot` ±0.8°, `dir` ±1.5°, `slide` ±1.5 kt, dot bearing ±3°,
dot distance ±1.5 kt. ≥ 5 exercises per level, ≥ 28 in total.

### Part ids (`data-part`, content in `content/parts.js`, es/en `{title, what, read, why}`)

Computer side: `outerScale`, `innerScale`, `hoursRing`, `index10`, `speedIndex`, `secondsIndex`, `convNaut` (NAUT/STAT/KM
group), `convFuel` (U.S. GAL/LITERS/FUEL LBS), `convLength` (METERS/FEET), `tasWindow`, `daWindow`, `tempStrip`, `cursor`.
Wind side: `trueIndex`, `driftScale`, `azimuth`, `grommet`, `slideCard`, `speedArcs`, `driftLines`, `windDot`.
